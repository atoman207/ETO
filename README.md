# 匠帳（たくみちょう）― 個別受注生産 案件・装置統合管理 デモ版

引合から原価確認・見積・取引審査・受注・工番発行・設計（BOM）・購買・製造・出荷納品・アフターサービスまで、
**案件と装置の情報を「一本の線」で管理する**、個別受注生産（ETO）向け業務システムの動作デモです。

---

## 起動方法

### 必要環境
- Node.js 20.9 以上（推奨：22 以上）

### 開発モードで起動
```bash
npm install
npm run dev
```
ブラウザで http://localhost:3000 を開いてください。

### 本番モードで起動
```bash
npm install
npm run build
npm start
```

> 初回表示時にデモデータ（顧客10社・案件32件・装置12台・サービス履歴15件 など）が自動で投入されます。
> 日付はすべて「本日」からの相対日数で生成されるため、いつ開いても自然な状態で確認できます。

## おすすめのデモ手順（約15分）

| # | 操作 | 確認できること |
|---|------|----------------|
| 1 | 右上「新規引合」→ 顧客・案件名・装置種別・処理能力を入力 | 入力に合わせて**類似の過去案件**と**金額の目安**が右側に表示 |
| 2 | 登録後、「原価」タブ →「この原価構成を適用」→「原価確認を完了して見積へ」 | 過去実績から原価を流用（ゼロから積算不要） |
| 3 | 「見積」タブ →「案件情報から見積書を作成」→「承認を申請する」→「承認（押印）」×2 | 顧客・件名・原価の**自動転記**、担当→課長→部長の**押印承認** |
| 4 | 「客先へ提出する」→「取引審査へ進む」→ チェックリスト →「申請」→ 承認 | 与信・受注残・粗利の自動集計による取引審査 |
| 5 | 「受注登録へ進む」→ 客先注文番号を入力 →「受注登録して工番を発行」 | **取引番号 → 見積番号 → 工事番号**の自動紐付け、工程の自動計画 |
| 6 | 「BOM」タブ →「類似案件から流用」「標準モジュール」「Excel貼付・CSV取込」 | **BOM入力負担の削減**（流用・テンプレート・貼付・品番自動補完） |
| 7 | 「購買依頼を作成」→「購買」タブで「発注する」「入荷登録」 | 仕入先ごとの購買依頼の一括作成 |
| 8 | 「製造」タブで進捗を更新 →「出荷・納品」で「納品完了を登録」 | 製造番号付きで**装置台帳に自動登録** |
| 9 | 「装置・アフター」→「サービス受付」→ 完了 →「案件化する」 | 装置単位の修理・改造履歴、**改造の案件化** |
| 10 | 画面上部の検索（`Ctrl + K`）で工事番号（例：`K26-108`）や顧客名を入力 | 全番号の横断検索 |
| 11 | 右上のユーザー名から「小林 翔太（サービス課）」に切替 | **原価のマスク表示**・操作権限の違い |

その他：「類似案件・原価比較」「装置台帳」「製造進捗（全工番ガント）」「資料管理（Google Drive 連携イメージ）」
「ご提案資料（要件整理・データ構造・システム構成・概算費用）」もご覧ください。

## 主な機能

- **案件管理**：11ステージの進行管理、次のアクション案内、保留・失注管理、引継ぎメモ、操作履歴
- **番号の自動採番と紐付け**：取引番号（T）→ 見積番号（M・版数付き）→ 工事番号（K）→ 製造番号（工番＋号機）→ サービス番号（S）、発注番号（P）
- **見積**：明細・原価・粗利率、出精値引き、改訂版、3段階の押印承認、御見積書の印刷・PDF保存
- **取引審査**：与信・受注残・粗利・納期の自動集計、チェックリスト、課長→役員承認
- **BOM（部品表）**：階層構造、類似案件からのユニット流用、標準モジュール展開、Excel貼付・CSV取込、品目マスタ自動補完、標準モジュール化、CSV出力
- **購買**：BOMから仕入先別に購買依頼を一括作成、発注・一部入荷・入荷・取消
- **製造**：工番発行時に納期から逆算した標準9工程を自動計画、ガントチャートで進捗更新、全工番一覧
- **出荷・納品**：出荷前チェック、納品完了で装置台帳へ自動登録（仕様スナップショット・保証期限）
- **装置台帳・アフターサービス**：製造番号単位の履歴、構成部品（交換部品の特定）、保証判定、使用部品・費用、改造の案件化
- **類似案件検索・原価比較**：仕様パラメータによる類似度検索、最大4件の横並び比較（原価構成・実績・故障件数）
- **資料管理**：案件ごとの標準フォルダ（01〜07）、ドラッグ＆ドロップ登録、帳票の自動作成
- **権限**：部署（ロール）×役職（承認段階）、原価のマスク表示、権限マトリクス
- **帳票**：御見積書・仕様書・社内注文書（工事指示書）― 角印・承認印付き、A4 印刷対応

## 表示デザインの変更（配色・フォント・動き）

画面右上の **パレットのアイコン**（または「設定・権限」→「表示デザインを変更」）から、すべての色・フォント・形・動きを変更できます。
変更は即座に全画面へ反映され、ブラウザに保存されます（再読込時もちらつきなく適用）。

| 分類 | 変更できる項目 |
|------|----------------|
| 配色 | 和の配色プリセット8種（藍染・若竹・江戸紫・墨と朱・桜・紺碧・柿渋・抹茶）／メインカラー・アクセントカラー・背景色・カードの色・印鑑の色（任意の色）／灰色のトーン（暖色・寒色・無彩色・メイン色寄り）／サイドメニューの色（濃色・メインカラー・墨色・淡色） |
| 文字 | 本文・見出し・装飾（帳票）・数字の4種類のフォントを個別に選択（Noto Sans JP、BIZ UDPゴシック、Zen角ゴシック、M PLUS 2、Zen丸ゴシック、IBM Plex Sans JP、しっぽり明朝、Noto Serif JP、Zen Old Mincho、BIZ UDP明朝 ほか）／文字の大きさ（85〜125%）／文字の間隔 |
| 形・質感 | 角の丸み／影の強さ／表示の密度（コンパクト・標準・ゆったり）／背景の質感（和紙）／和柄（青海波・七宝・市松） |
| 動き | アニメーション（なし・控えめ・軽やか）／季節の演出（桜・紅葉・雪・蛍・季節に応じて自動）／パソコンの「アニメーションを減らす」設定に従うかどうか |

- メインカラー・アクセントカラーは1色を選ぶだけで、薄い色〜濃い色の11段階が自動で生成されます。白文字が読みにくい明るい色を選んだ場合は、読みやすさ（コントラスト）を保つよう自動で明度を補正します。
- 「同梱」「システム」と表示されたフォントはオフラインでも使えます。その他のフォントは Google Fonts から必要な文字だけを読み込みます。
- 「書き出し」「読込」で表示デザインを JSON ファイルとして共有できます（社内で統一した見た目に設定する場合など）。
- 帳票（見積書など）は表示倍率の設定に関係なく、A4 の実寸で表示・印刷されます。

### 開発者向け：デザイントークン
色・フォント・角丸・影・余白はすべて CSS 変数（`src/app/globals.css` の `@theme`）で定義しています。

| 変数 | 用途 |
|------|------|
| `--color-ai-50〜950` | メインカラー（ボタン・見出し・選択状態） |
| `--color-shu-50〜950` | アクセントカラー（強調ボタン・現在地） |
| `--color-stone-50〜950` | 灰色（文字・罫線） |
| `--color-kinari` ／ `--color-surface` ／ `--color-inshu` | 画面背景 ／ カード・入力欄 ／ 印鑑 |
| `--color-sidebar-*` | サイドメニュー |
| `--font-sans` ／ `--font-heading` ／ `--font-mincho` ／ `--font-num` | 本文 ／ 見出し ／ 装飾・帳票 ／ 数字 |
| `--radius-*` ／ `--shadow-card` ／ `--shadow-lift` ／ `--spacing` | 角丸 ／ 影 ／ 余白の基準 |

プリセットやフォントの追加は `src/lib/theme.ts` の `PRESETS` ・ `FONTS` に1行追加するだけで、設定画面に自動で表示されます。

## データの保存について

- 本デモのデータは**ブラウザのローカルストレージ**に保存されます（サーバーへの送信はありません）。
- 「設定・権限」→「デモデータを初期化」で初期状態に戻せます。「全データを出力（JSON）」も可能です。
- Google Drive・Gmail 等には接続していません（連携イメージとして画面を用意しています）。

## 技術構成

| 項目 | 内容 |
|------|------|
| フレームワーク | Next.js 16（App Router）／ React 19 ／ TypeScript |
| スタイル | Tailwind CSS 4 ＋ CSS 変数によるデザイントークン（OKLCH 色空間で配色を自動生成） |
| フォント | Noto Sans JP（本文）／しっぽり明朝（帳票・見出し）― セルフホスト、その他は Google Fonts から選択可 |
| アニメーション | Framer Motion |
| 状態管理 | Zustand（ローカルストレージ永続化） |
| グラフ | Recharts |

### ディレクトリ構成
```
src/
├─ app/
│  ├─ (main)/            … 業務画面（ダッシュボード・案件・顧客・装置・サービス 等）
│  └─ print/             … 帳票（見積書・仕様書・社内注文書）
├─ components/
│  ├─ case/              … 案件詳細の各タブ・ステージ表示・受注/工番モーダル
│  ├─ bom/               … BOM 流用・テンプレート・取込モーダル
│  ├─ layout/            … サイドバー・ヘッダー・Ctrl+K 検索
│  ├─ theme/             … 表示デザイン設定・和柄・季節の演出
│  └─ ui/                … 共通部品（ボタン・モーダル・印鑑 等）
└─ lib/
   ├─ theme.ts           … デザイントークン・配色プリセット・フォント定義
   ├─ color.ts           … 色計算（段階生成・コントラスト補正）
   ├─ types.ts           … データモデル定義
   ├─ store.ts           … 業務ロジック（採番・承認・受注・BOM・購買・納品 等）
   ├─ seed.ts            … デモデータ生成
   └─ similarity.ts      … 類似度算出
```

### 本番化に向けて
業務ロジックは `src/lib/store.ts` のアクションに集約しています。本番環境では各アクションを
API（Cloud Run）＋ データベース（Cloud SQL / PostgreSQL）呼び出しに置き換え、
Google Workspace の SSO・Drive API と連携する構成を想定しています（詳細は画面内「ご提案資料」参照）。
